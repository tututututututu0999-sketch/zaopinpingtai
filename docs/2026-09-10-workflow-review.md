# 创作流程架构与排版审查

审查日期：2026-09-10。范围：参考选择、独立上传、报告、提示词、实际生图参考传递；保留现有 PostgreSQL、向量检索和 Luna / Terra / image2 分工。

## 结论与证据

核心不变量是：生成结果必须对应一份明确确认的需求和参考快照。图片用途、说明或文件发生变化，旧提示词不能继续代表新选择；网络请求成功也不能代表模型生成成功。

现场发现两类独立问题：

1. 网关能返回 HTTP 200 和 SSE 初始化事件，但随后返回 `response.failed` / `upstream_error`。Terra 的极简测试也失败；去掉额外推理参数后，约 13 秒仍返回上游错误。因此不能把问题仅归因于长提示词或网站按钮。Luna 的 Responses 测试曾约 2 秒成功，另一轮 Chat 测试超过 45 秒，说明上游还存在不稳定性。
2. 原先所有设计任务都依赖套系检索；上传只是已有任务的补充。前端又有上传前说明和上传后说明两处输入，且缺少跨异步请求的参考版本校验。单改布局或延长超时不能解决这些问题。

## 六个审查维度

| 维度 | 问题与本次处理 | 影响及剩余边界 |
| --- | --- | --- |
| 根因 | 共享模型传输层改为读取流式结果，只接受完成事件；流内错误、半截结果、输出长度中断均失败。报告及其修复共用 60 秒预算；减少视觉摘要与完整档案的重复输入。 | 及时暴露真正的上游失败，保留当前内容；不伪造成功，不自动换模型。上游可用性尚未恢复。 |
| 同类扫描 | 报告、提示词、提示词修订、参考识别、参考约束校验统一经过模型响应读取器；报告与提示词均绑定参考修订号。 | 修复不限于一个按钮。图片生成仍使用独立图片接口，不误把图片响应当文本流。 |
| 外溢影响 | 引入 `catalog` / `upload` 参考来源，共享报告、卖点规则、提示词和生图管线。独立上传按任务保存，不写素材库。 | 不要求上传图先向量化，也不绕过正式素材的审核资格；上传不会自动变成可检索素材。 |
| 维护成本 | 抽出统一上传编辑组件、参考失效函数、参考计划适配器和模型流读取器；沿用已有主题、Lucide 和 beUI。 | 避免复制两套生成业务。现有大页面仍较长，后续宜按需求、参考、生成拆分状态管理。 |
| 向前兼容 | 新增数据库字段默认 `catalog` 和修订 0；旧任务与历史保留。旧提示词缺失修订号按 0 校验。 | 尚未修改参考的旧任务可沿用；修改后必须重新确认 / 组合，不允许旧提示词覆盖新参考。迁移可重复运行。 |
| 边界 | 验证空上传、损坏图片、格式与 MIME 不一致、多图上限、单 IP 限制、未保存说明、识别期间修改、旧报告回写、需求过期、失败重试、移动端长文件名。 | 单任务最多 6 张，单个文件 12MB，图片像素数受限；约束无法验证时停止，不自动放宽。 |

## 新流程

需求分析 → 确认方向 → **套系检索 / 独立上传** → 确认参考 → 简短报告 → 选择画幅与卖点结构 → 组合提示词 → 人工确认 → 生图。

独立上传确认时，Luna 识别并保存任务专属视觉快照；识别失败不确认。修改上传说明或移除图片后撤销当前报告、提示词及上传确认；生成历史不删除。报告失败重试时，已完成的上传确认可以复用。

服务端报告与提示词返回前检查修订号，保存时再次在行锁内检查，开始生图也按同一修订号认领任务。生成中的任务不能修改参考。图片请求仍传入实际文件，并记录与顺序一致的参考用途及来源，不只传文字描述。

## 排版

- 需求确认底部并列两个入口，手机纵向排列。
- 套系图与本次上传左右两栏；纯独立上传时去掉空白套系列。
- 每张上传图只保留一处使用说明，保存 / 移除采用同一家族图标；长文件名换行。
- 沿用用户主题中的灰阶、蓝色强调与暗色模式；等待态复用 beUI，展示真实等待秒数，尊重减少动态效果设置，不展示虚构百分比。

## 后续风险

1. **外部阻塞：** 网关上游生成仍可能失败或超时。模型列表、数据库健康都不能替代实际生成健康；目前不把模型可用性混入普通健康接口，避免每次探测付费。
2. **任务恢复：** 文本生成仍是有界同步请求，并非持久后台队列。页面关闭时不能保证恢复尚未返回的模型结果；任务和已生成历史仍在数据库中。后续若需离开页面后继续处理，应增加任务列表与持久文本作业，而不是不断延长 HTTP 超时。
3. **并行确认：** 多标签页同时确认同一份上传可能重复消耗识别调用，但只有符合当前修订号的结果能发布。下一步可用持久作业去重来消除重复成本。
4. **模型遵循性：** 已有提示词冲突检测能阻止已知自相矛盾，无法证明模型一定严格复刻版式或角色。应保留参考预览、来源记录和生成结果人工确认。
