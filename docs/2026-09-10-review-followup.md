# 上传、审核与报告修复记录

## 界面

- 独立上传与报告中的上传区使用同一组件；删除重复二级标题。多图以自适应卡片网格排列，手机单列，字号和灰阶沿用主题。
- 缩略图按图片原比例展示，限制最大宽高；说明框默认两行，每图仅一处说明，保存/删除沿用统一图标。
- 审核队列仅隐藏 `READY` 行，不删除素材、档案或向量。已发布统计保留；项目库继续查看正式素材。
- 视觉档案按六组显示分类标签、字段和值，观察依据折叠；编辑弹窗不再重复同一份摘要。若已有版本与新候选不同，提供折叠对照。
- 手机补充项目库选择入口，避免已发布内容在审核队列隐藏后无法访问。

## 故障证据与修复

出错任务 `561b65de-61bc-46b0-89c4-0cecf90a0979` 的两张上传图均已确认，状态为 `REFERENCE_CONFIRMED`，失败在报告步骤。

发现宿主机 8443 转发进程停止，导致容器请求直接连接失败。恢复后 Terra 短请求约 3–5 秒成功。转发现由当前用户 LaunchAgent `com.zyb.visual-gateway` 管理，登录启动、退出恢复；配置源保存在 `scripts/com.zyb.visual-gateway.plist`。补上 socket 双向关闭和空闲超时，避免旧连接残留。没有更改密钥或模型分工。

完整报告仍出现上游 `upstream_error`，不应仅归因于网络。对照请求显示：精简上下文的一次请求约 9 秒成功；完整参考数据但去掉可选 temperature / response_format 参数的一次请求约 42 秒成功。两次单独成功不是因果证明，也不能证明网关长期稳定。

应用侧采取可维护的改动：

1. 报告阶段去掉重复检索数据和审核置信度/依据，保留原始需求、用户限制、各组视觉结构和参考用途；不截断文案。
2. Chat 请求不发送可选采样及 JSON 模式参数，仍严格解析并校验 JSON 和字段。
3. 仅 `upstream_error` 且剩余时间足够时，使用相同模型和内容重试一次，共享原始 60 秒预算；授权、超时和无效内容不盲目重试。
4. 上传确认与报告生成分开显示。报告失败后保留已确认图片，再点继续不会重复识别。

## 验证边界

通过类型检查、Lint、构建、报告字段保真测试、模型传输与重试测试、数据库隔离集成测试，以及 1440px / 390px 多图上传、审核去重、项目库详情交互测试。没有运行付费图片生成。

上游仍可能间歇失败，不能用成功的短请求证明完整创作总能成功。当前实现保留具体失败阶段和已有数据，不自动切换 Luna/Terra 或伪造报告。

最终部署后，使用上述真实任务调用 `/api/brief/report` 返回 HTTP 200，耗时 15.75 秒，规则校验通过、绑定参考修订 4。报告明确要求用指定 IP 肖像替换原机械插画。没有保存测试报告、修改确认状态或调用图片生成。正式页面的 1440px / 390px 上传回归也通过。
